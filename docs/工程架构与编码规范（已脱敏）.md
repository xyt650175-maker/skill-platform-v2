# 前后端工程架构与编码规范


## 一、工程架构及核心框架

### 1.1 整体架构

系统采用**前后端分离 + 多模块服务化**架构:

- **前端**: 单页应用(SPA),负责可视化编排、调试交互、管理后台界面
- **后端**: Spring Boot 单体应用(多模块),提供 REST API,集成 Git/NAS/K8s 等基础设施
- **基础设施**: TDSQL(业务数据)、Redis(分布式锁/缓存)、NAS(文件存储)、Git(版本管理)、K8s(运行时)

### 1.2 前端架构

| 层次 | 职责 | 技术栈 |
|------|------|--------|
| 视图层 | 页面与组件渲染 | Vue 3 (Composition API) + Element Plus |
| 状态层 | 全局状态管理 | Pinia(主) |
| 路由层 | 动态路由与权限 | Vue Router 4 |
| 请求层 | HTTP 封装与拦截 | Axios(统一 baseURL + 拦截器) |
| 工程化 | 构建/校验/规范 | Vite + TypeScript + ESLint + Prettier |
| 可视化 | 流程编排/画布 | Vue Flow + LogicFlow |
| 代码编辑 | 多语言高亮编辑 | CodeMirror 6 + Ace Editor |
| 图表 | 数据可视化 | ECharts |

### 1.3 后端架构

| 层次 | 职责 | 技术栈 |
|------|------|--------|
| Web 层 | REST 接口、参数校验、拦截器 | Spring Boot Web + Starter |
| Service 层 | 业务逻辑编排 | Spring + 自定义 Logic 层 |
| Logic 层 | 复杂业务规则、跨表聚合 | 自封装 Logic 类(Service 调用) |
| DAO 层 | 数据持久化 | MyBatis-Plus 3.5.5 + MyBatis XML |
| 数据库 | 业务数据存储 | TDSQL |
| 缓存/锁 | 分布式锁、会话 | Redis(仓库级锁) |
| 文件存储 | 版本包、草稿、回滚文件 | NAS(本地挂载) |
| 版本管理 | Skill/Agent 代码版本控制 | JGit 5.12 + Git Remote |
| 鉴权 | JWT 认证、RBAC | JJWT + 自定义拦截器 |
| 定时任务 | 清理过期文件、数据同步 | 批量 |
| 部署 | 容器化 | K8s(fabric8 client)+ Tomcat |

### 1.4 请求流转

```
浏览器 → Vite Dev Server(代理 /race-api) → Spring Boot
    → 单点+权限
    → Controller → Service → Logic → DAO → TDSQL
    → GitService(JGit) / NAS / Redis
```

## 二、编码规范

### 2.1 前端模块结构规范

每个业务模块(views 下一级目录)应包含以下子目录:

```
src/views/<module>/
├── index.vue              # 模块入口页面(列表/主视图)
├── components/            # 模块私有组件
│   ├── XxxDialog.vue      # 弹窗组件(命名:功能+类型)
│   ├── XxxDrawer.vue      # 抽屉组件
│   └── XxxTable.vue       # 表格组件
├── hooks/                 # 模块级组合式函数(可选)
│   └── useXxx.ts
├── types/                 # 模块级类型定义(可选)
│   └── index.ts
└── utils/                 # 模块级工具函数(可选)
    └── index.ts
```

#### 全局目录规范

```
src/
├── api/                   # 接口定义(按业务域拆分 .ts 文件)
├── assets/                # 静态资源(图片/字体/svg)
├── components/            # 全局通用组件(跨模块复用)
├── layout/                # 布局组件(Navbar/Sidebar/GitInfoDialog 等)
├── router/                # 路由配置
│   ├── modules/           # 按业务域拆分路由
│   └── constant.ts        # 常量路由
├── stores/                # Pinia 状态管理
│   └── modules/           # 按业务域拆分 store
├── styles/                # 全局样式(SCSS)
├── utils/                 # 全局工具函数
│   ├── request.ts         # Axios 实例(统一 baseURL/拦截器)
│   ├── auth.ts            # Token 管理
│   └── validate.ts        # 校验工具
├── hooks/                 # 全局组合式函数
├── directive/             # 自定义指令
└── views/                 # 业务页面(按模块组织)
```

#### 前端编码约定

1. **组件命名**: PascalCase(如 `SkillFlex.vue`、`VersionManageDrawer.vue`)
2. **API 定义**: 每个 .ts 文件对应一个业务域,函数名用 camelCase,导出具名函数
3. **状态管理**: 跨模块共享状态用 Pinia;组件内私有状态用 `ref`/`reactive`
4. **请求封装**: 统一用 `@/utils/request` 实例,禁止直接 `new Axios()`
5. **类型**: 严格使用 TypeScript,接口参数和返回值必须显式标注类型
6. **代码编辑器组件**: 使用 `:model-value` + `@update:modelValue`,禁止 `v-model`

### 2.2 后端模块结构规范

每个业务模块(对应一个数据库表/业务域)应包含以下分层:

```
com.company.llmaif.<module>/
├── controller/            # REST 接口(可选,部分模块共用 controller)
│   └── XxxController.java
├── service/               # 服务接口
│   ├── impl/
│   │   └── XxxServiceImpl.java
│   ├── vo/                # 视图对象(返回前端的 DTO)
│   │   └── XxxVO.java
│   └── IXxxService.java
├── logic/                 # 业务逻辑层(复杂规则、跨表聚合)
│   └── XxxLogic.java
├── dao/                   # 数据访问层
│   ├── entity/            # 数据库实体(@TableName)
│   │   └── XxxEntity.java
│   ├── XxxDAO.java        # MyBatis-Plus Mapper 接口
│   └── XxxDAO.xml         # MyBatis XML(复杂 SQL)
├── enums/                 # 模块常量/枚举(可选)
│   └── Constants.java
└── util/                  # 模块工具类(可选)
```

#### 后端编码约定

1. **分层职责**:
   - `Controller`: 参数校验、调用 Service、返回 `ResponseBase`
   - `Service`: 业务编排,调用 Logic 和 DAO
   - `Logic`: 复杂业务规则、跨表聚合、事务边界
   - `DAO`: 单表 CRUD,复杂查询走 XML

2. **返回格式**: 统一使用 `ResponseBase<T>`(`code`/`message`/`data`),`code="0"` 为成功

3. **实体规范**:
   - 所有实体继承 `Serializable`
   - 使用 `@TableName`/`@TableField`/`@TableId` 注解
   - 逻辑删除字段用 `@TableLogic`,默认值 `is_deleted=0`
   - TDSQL 保留字(`key`/`value`/`order`)必须用反引号包裹

4. **Git 操作**:
   - 统一通过 `GitService` 调用 JGit,禁止在 Service 直接 new Git
   - 必须使用仓库级 Redis 锁(key: `git:repo:{repoHash}`)
   - `git.add()` 必须分两步:先 `setUpdate(true)` 暂存修改/删除,再 `add()` 暂存新文件

5. **定时任务**: 使用批量统一处理

6. **异常处理**: 业务异常抛 `AgentException`,全局由 `GlobalExceptionHandler` 捕获

7. **路径安全**: 文件路径拼接禁止包含冒号(`:`)等 OS 非法字符,时间戳用于路径时格式化为 `yyyyMMdd_HHmmss`

## 四、版本管理约定

| 场景 | 格式 |
|------|------|
| 测试版本号 | `x.y.z`(如 `1.0.0`) |
| 草稿版本标识 | `yyyyMMdd_HHmmss`(路径用)/`yyyyMMdd.HHmm.ss`(展示用) |
| Git Tag | `{skill-name}-{x.y.z}`(无 `v` 前缀) |
| 草稿 Git Tag | 无 |
| NAS 草稿路径 | `/agent_nas/skills/drafts/{skill-name}/{yyyyMMdd_HHmmss}/{skill-name}.zip` |
| NAS 测试版本路径 | `/agent_nas/skills/{skill-name}/{x.y.z}/{skill-name}.zip` |
| NAS 版本保留 | 3 天 TTL,当前版本永久保留  批量决定|
| Git 锁 key | `git:repo:{repoHash}`(仓库级,30 秒超时) |
