# SKILL 开发规范

> 本文件由业务方提供并纳入项目。平台的 AI 生成、导入校验、草稿保存与定版流程均以此为准。

## 一、强制规范

### 1. 文件结构规范

SKILL 文件结构必须遵守：

```text
skill-name/
├── SKILL.md                 （必须存在）
│   ├── YAML 元信息          （必须存在）
│   │   ├── name:            （必须存在）
│   │   └── description:     （必须存在）
│   └── 具体步骤/使用说明     （必须存在）
├── 可选项
├── scripts/                 - 可执行代码
├── requirements.txt         - 依赖管理（如果使用 Python 脚本）
├── references/              - 文档和参考材料
└── assets/                  - 静态文件
```

### 2. 主入口文件命名

- 必须命名为 `SKILL.md`（全大写）。
- 禁止使用 `README.md`、`readme.md` 或其他名称。

### 3. YAML 前言区格式

前言区和正文之间必须用 `---` 分隔：

```yaml
---
name: xxx          # 必须
description: xxx   # 必须
dependency:        # 可选
---
```

### 4. 资源文件路径

- 应使用相对路径。
- `references` 及 `assets` 文件夹中提及的文件应真实存在。
- 避免使用绝对路径或外部 URL。

### 5. 脚本质量

- 语法应正确且通过单元测试。
- 应用简洁的示例代替冗长的解释。
- 应仅补充该任务特有的特殊规则。

### 6. 表达方式

- 应使用“禁止”“不要”“避免”等否定性指令（黑名单）。
- 应统一使用祈使语气/不定式。
- 长文件资源应加目录（超过 100 行的 reference 文件）。

### 7. 发布前清理

- 应清理临时代码、缓存、测试产物和日志。
- 临时文件应移动到 `assets/` 或 `references/` 目录。

### 8. 依赖管理

- 应使用 `requirements.txt` 记录依赖信息。

## 二、应遵守规范

### 1. description 规范

- 长度应为 100–150 字符。
- 应包含：
  - 能力价值（能解决什么问题）
  - 触发场景（何时使用）

### 2. dependency 字段格式

若存在，格式应正确：

```yaml
dependency:
  python:
    - jinja2>=3.1.0
```

### 3. 目录命名

- 应仅包含小写字母、大写字母、数字及下划线。
- 禁止以连字符开头或结尾。

## 三、应避免规范

### 1. 正文长度

- `SKILL.md` 正文不应超过 500 行。

### 2. 多余文档

- 不应存在 `README.md` 等额外文档。

### 3. 空文件/空路径

- 不应存在空文件/空路径。
- 如 `SKILL.md` 中不涉及 `references` 需求，则无须生成该文件夹。

### 4. 硬编码内容

- 不应在 SKILL 中生成技能构建者本地相关的硬编码内容。
- 禁止包含本地路径（如 `C:\Users\...`）。

### 5. 版本混乱

- 不应同时存在多版本的脚本。
- 不应存在不同版本功能差异描述。

### 6. 技能耦合

- Skill 不应整合其他 skill 的代码。
- 应保持 skill 的原子性。

## 四、稳定性增强方法

### 1. 防止执行过程中被修改

关键防护策略：

| 防护层级 | 具体方法 | 作用 |
|---|---|---|
| 角色分离 | 使用 System Role 承载 Skill 定义，User Role 承载输入 | 防止用户输入覆盖系统指令 |
| 明确边界标记 | 使用 `<!-- -->` 或特殊分隔符包裹关键内容 | 视觉和语义上区分可修改与不可修改区域 |
| 指令强化 | 在 Skill 开头和结尾重复“禁止修改”指令 | 利用首尾强化效应提升遵循度 |
| 输入消毒 | 过滤用户输入中的 `system:`、`assistant:` 等角色标记 | 防止角色混淆攻击 |
| 长度限制 | 限制用户输入长度（如 ≤2000 字符） | 防止长文本注入攻击 |

示例：

```text
<!-- SKILL_DEFINITION_START -->
# 以下内容为大模型 Skill 定义，禁止修改
<!-- DO_NOT_MODIFY: This section contains critical skill definitions. -->
<!-- SKILL_DEFINITION_END -->
```

### 2. 降低模型幻觉

核心原则：具体明确，消除歧义。

技巧：

- 鼓励弃权：允许模型说“不知道”。
- 输出约束：限制格式和长度。
- 少样本示例：提供正反例。
- 思维链（CoT）：要求逐步推理。
- grounding 指令：要求引用来源。
- 重复关键指令：首尾重复核心约束。
- 温度控制：降低 temperature 至 0.1–0.3。

### 3. 充分发挥泛化能力

技巧：

- 抽象层设计：提取通用模式。
- 少样本变体：展示多种正确形式。
- 指令改写兼容：测试同义表达。
- 上下文扰动：增强鲁棒性。
- 格式解耦：分离任务逻辑与输出格式。

### 4. 多 Skill 编排模式

三种基本模式：

- **顺序执行**：步骤有依赖关系。
- **并行执行**：任务可分解为独立子任务。
- **条件分支**：根据中间结果动态选择路径。

核心原则：模型决策，应用执行。

## 六、行内需要遵守的强制规范（SKILL 上半部分）

```json
{
  "version": "1.0.0",
  "name": "deepresearch",
  "name_zh": "企业级知识库问答和深度研究",
  "description": "基于企业级知识库的智能问答与深度研究技能，可以处理从简单知识问答到复杂主题的研究任务。",
  "tags": "日常办公,code,wps",
  "runEnv": "windows,uos,arm",
  "digestValue": "sdfsdfsdfwefsdf",
  "executeAbility": "python,exe,js",
  "changeRecord": "版本更新说明",
  "license": "MIT",
  "clawVersion": "5.2"
}
```

字段说明：

1. `version`：必填，最大 100 个英文字符。
2. `name`：必填，最大 80 个字符。
3. `name_zh`：必填，最大 80 个字符。
4. `description`：必填，最大 600 个字符。
5. `tags`：必填，最大 150 个字符。
6. `runEnv`：必填，全部兼容填写 `all`，最大 128 个英文字符。
7. `digestValue`：由脚本自动生成 MD5 值，最大 512 个英文字符。
8. `executeAbility`：可选，最大 150 个字符。
9. `changeRecord`：可选，最大 150 个字符。
10. `license`：可选，最大 150 个字符。
11. `clawVersion`：可选，适用的 claw 版本，最大 100 个英文字符。
