# Skill 平台使用手册

## 1. 访问与登录

本地联调地址：`http://127.0.0.1:5177/login`。

- 管理员账号：`admin / admin123`
- Skill 开发入口：左侧「技能」展开后的「技能开发」
- Skill 管理入口：左侧「技能」展开后的「技能管理」

生产环境应接入企业统一认证；本地账号仅用于联调。

## 2. 创建与导入 Skill

在「技能管理」点击「+ 创建 Skill」，或在「技能开发」点击「+ 新建」，再选择开发模式。

### 在线创建

1. 选择关联智能体（也可暂不关联）。
2. 选择「在线创建」。
3. 填写名称、简介、初始版本和可见范围。
4. 可见范围只支持「私有」和「团队」；平台不允许创建公共 Skill。
5. 创建后进入工作台，通过 AI 对话或代码编辑器完善文件。

### 从本地导入

1. 选择「从本地导入」。
2. 上传 ZIP 包；包内必须含 `SKILL.md`，若已声明版本，必须为 `x.y.z`。
3. 可选择私有/团队可见和企业 Git 连接。
4. 校验成功后点击「导入」。

### 从企业 Git 导入

1. 选择「从 Git 导入」。
2. 在「管理内网连接」新增企业仓库连接；令牌只发送到后端并加密保存，不会回传浏览器。
3. 点击「加载 Skill」，选择分支或 Tag，再勾选要导入的标准 Skill 包。
4. 点击「导入」。

企业环境禁止使用公网 Git；仓库地址应为企业内网 GitLab/Gitea 等服务。

## 3. 标准 Skill 文件结构

每个 Skill 由下列四个同级项构成：

```text
SKILL.md
requirements.txt
references/
scripts/
```

- `SKILL.md`：Markdown 说明、用途、输入输出和版本；不使用 YAML frontmatter。
- `requirements.txt`：Python 依赖清单。
- `references/`：业务说明、数据源配置与测试数据。
- `scripts/`：入口脚本及校验、Mock 等实现文件；入口默认为 `scripts/main.py`，必须提供 `handle(input_data)`。

文件浏览器默认折叠目录，点击 `references/` 或 `scripts/` 展开。点击文件后可预览，点击「编辑」修改并保存。

## 4. AI 生成、模板与测试数据

1. 在左侧选择推荐提示词或输入自己的需求。
2. 选择「测试数据模板」。模板用于约束本轮生成的输入字段、输出字段、业务规则和初始案例。
3. 点击「查看数据」查看完整模板；业务人员可通过模板管理上传或维护团队模板。
4. AI 生成的变更会先进入 Diff 预览。检查后点击「应用变更」，再保存草稿。

模板不是最终调试数据。生成完成后，业务人员在 `references/test-data.json` 填入完整案例。每条案例应包含：

```json
{
  "id": "normal-query",
  "name": "正常产品查询",
  "input": {"product_code": "000001", "query": "产品信息查询"},
  "expected": {"contains": {"product_code": "000001", "risk_level": "R2"}}
}
```

## 5. 保存、协作与版本

- 「保存草稿」保存当前全部文件，并提示下一步执行调试。
- 保存包含草稿修订号。若其他成员先保存，后保存者会得到“草稿已被其他成员更新”的提示，应刷新后合并再保存。
- 草稿保存会提交平台内部 Git，并生成可回溯快照；草稿快照由定时任务清理。
- 「提交评审」只创建待审记录，不会创建 Git tag 或发布包。审核中心选择「通过并定版」后，才会同步写入 `SKILL.md` 的「当前版本」、生成同名 Git Tag，并将 ZIP 归档到 NAS 发布目录；驳回会退回草稿。

建议流程：保存草稿 → 调试通过 → 提交评审 → 审核通过后定版。

## 6. 调试与日志

在工作区选择「调试」。

### 单条调试

输入 JSON，例如：

```json
{"product_code": "000001", "query": "产品信息查询"}
```

点击「运行调试」。页面展示：运行结果、耗时、状态、依赖调用次数和 Token 消耗；失败时展示 stderr/堆栈。

### 全量用例

点击「运行全部用例」，系统逐条读取业务测试数据中的案例，运行完整 Skill 工作区，并将输出与“预期包含字段”比对。结果会显示通过数量，例如 `4/4 通过`。

### 日志

选择「日志」查看保存、生成和调试记录。每条调试记录支持展开完整日志和单条下载；「批量下载」可导出全部记录。

本地调试是“受限本地进程”：临时目录、Python 隔离模式、3 秒超时。它不是容器级安全沙箱；生产部署需接入企业容器沙箱后再承载不可信代码。

## 7. 智能体、评测和流水线

- 在智能体中心创建智能体，可配置画布、子智能体及 Skill 挂载。
- 将已定版或待测 Skill 挂载到目标智能体，配置别名和是否启用。
- 在智能体评测创建评测任务，选择智能体、版本、数据集和执行范围。创建后初始状态是“待执行”；只有实际执行器更新任务状态后，才会显示“运行中/已完成”，平台不会伪造评测结论。
- 在流水线页面创建或更新 factory/skill 流水线，定义阶段配置。

## 8. 模型与数据库 API

模型调用使用后端 `TOKEN_PLAN_API_KEY`。未配置时，页面会明确提示“未配置 TOKEN_PLAN_API_KEY，无法调用模型”；不得将密钥写入前端代码、浏览器本地存储或 Skill 文件。

数据库 API 在 `references/data-source.json` 指定数据源类型、服务地址和环境变量名。实际数据库凭据必须由后端安全代理或企业密钥管理服务注入，不由浏览器保存。

## 9. 运行本地验收

启动服务后，在项目根目录执行：

```bash
API_BASE=http://127.0.0.1:8083/race-api ./scripts/verify-platform.sh
```

脚本会覆盖登录、私有化、标准文件保存、调试成功/失败、提交评审不提前定版、审核通过定版、智能体挂载、评测任务状态更新和流水线创建。它会产生带 `verify-` 前缀的临时测试数据。
